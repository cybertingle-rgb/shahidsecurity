# Third-Party Integrations

Full depth: manual §6 (API and Integration Documentation, "Third-party integrations" subsection).

For every integration below, the **variable names** it needs are in `ENVIRONMENT_VARIABLES_REFERENCE.md` — this document covers what each integration does and how to tell if it's actually working, not credentials.

| Integration | What it's for | How to verify it's actually working | Failure mode if misconfigured |
|---|---|---|---|
| **Google OAuth (two separate applications)** | Admin-staff sign-in to connect Search Console / Analytics / Business Profile integrations, and a separate Learn student sign-in | `/admin/dashboard/google` shows a connected state with a recent sync timestamp | A redirect-URI mismatch (protocol, trailing slash, or host not matching exactly what's registered in Google Cloud Console) — this has happened once already in Learn registration (commit `af1aa12`). Almost never a credentials problem when it fails specifically at the redirect step |
| **FX rate service (open.er-api.com)** | Converts USD prices to a visitor's local currency for *display only* on `/pricing/` — never the actual charge | `GET /api/public/pricing-plans?currency=AED` — `usedFallback: true` means no cached rate yet, not necessarily broken | Falls back to showing USD automatically — never shows a silently wrong converted number. Free, keyless, no SLA; confirm an external cron actually hits the secret-gated refresh endpoint on a schedule (~6 hours recommended) — nothing in the code self-schedules this |
| **Cloudflare Turnstile** | Bot protection on the public contact form | Submit the contact form and confirm a `leads` row is created | If the public site key is empty, both the client widget and server-side check intentionally skip — a documented fallback, not a crash, but it means no bot protection until a real key is set |
| **SMTP / email (two unrelated paths)** | The Astro contact form uses PHPMailer with a config file outside the repo; the gateway has its own separate SMTP variables for whatever it sends directly | Submit the contact form and confirm the email arrives; separately test any gateway-sent mail | A failure in one path says nothing about the other — they are not the same mail pipeline, despite looking similar |
| **Anthropic (Claude) — Luna chat** | Powers the AI chat beyond a local FAQ fast-path | Ask Luna a question that doesn't match any FAQ and check for a real (non-generic) response | The route explicitly checks for the API key — the FAQ fast-path still works with none set; only non-FAQ questions fail gracefully. A past "could not reach" error was traced to a network/response-parsing issue, not the key itself — check the actual error before assuming a credentials problem |
| **GitHub (`@octokit/rest`) — admin "publish" integration** | The admin dashboard's content/SEO publish actions commit changes back to **this same repository** programmatically | A successful publish action creates a real commit, visible in `publications` table (`commitSha`) and in the repository's own history | The token used has write access to this project's source — treat it with deploy-credential-level care, not as an ordinary API key. A revoked or expired token breaks the publish feature only, not the rest of the site |
| **Payment provider** | Not confirmed active | No live call site was traced for `PAYMENT_PROVIDER`/`PAYMENT_API_KEY`/`PAYMENT_SECRET` | The Learn checkout flow appears to use a manual-payment-pending pattern (an admin manually confirms payment) rather than an automated gateway charge. **Do not describe a payment gateway as operational without verifying this directly first** |

## General diagnostic pattern

Most of these integrations degrade gracefully by design — a missing key skips a feature rather than crashing the app (Turnstile, FX rates, the Anthropic key's non-FAQ path). When something that should be live isn't working, first confirm the integration's own health indicator (where one exists, e.g. `/admin/dashboard/google`) before assuming a code regression.
