If your business has adopted an AI assistant, automation tool, or agentic platform in the past year, there is a good chance it talks to your other systems through the **Model Context Protocol (MCP)** — an open standard, introduced by Anthropic in late 2024, that has become the default way AI agents connect to outside tools and data. It solved a real integration headache. It has also, through 2026, become one of the fastest-growing sources of new AI-related vulnerabilities — and most businesses adopting it have no idea it is the layer they should be securing.

## What MCP actually does

Before MCP, connecting an AI model to an external tool — a database, a file system, a SaaS platform — typically meant writing custom integration code for every single combination. MCP replaces that with a standard client-server model: an **MCP server** exposes a tool or data source in a consistent format, and any **MCP client** (the AI application) can connect to it without bespoke code. It is, functionally, a universal adapter between an AI agent and whatever it needs to read, search, or act on.

That same design is what makes it a security concern. An MCP server is, in effect, a new kind of privileged integration point — one that an AI model can now reach, invoke, and chain together with other tools, often with far less operator oversight than a traditional system integration would get.

## Why security researchers are worried

Industry reporting through 2026 paints a consistent picture of a standard that grew faster than its security practices did:

- **Volume of new vulnerabilities.** Security researchers tracked more than 30 CVEs filed against MCP servers, clients, and related infrastructure in just the January–February 2026 window alone — a sign of how much ground this ecosystem covers and how immature much of it still is.
- **A dedicated OWASP project.** OWASP has launched a Top 10 specifically for MCP implementations, covering risks like token mismanagement, tool poisoning (a malicious or compromised tool definition tricking the agent into unsafe actions), and excessive permission scope.
- **Familiar vulnerability classes, at agent speed.** Security researchers presenting at RSAC 2026 warned that MCP reintroduces well-understood problems — server-side request forgery, privilege escalation, insecure default configuration — but at the speed and scale an autonomous agent can operate, rather than the speed a human operator would.
- **Exposed infrastructure at scale.** Research tracking exposed MCP servers has put the count in the hundreds of thousands, many running with weak or no authentication, reachable directly from the internet.
- **Government attention.** The NSA's AI Security Center published specific design guidance for MCP security in May 2026 — a strong signal that this has moved from an engineering curiosity to a recognized risk category worth a formal advisory.

This sits alongside, but distinct from, risks covered in our articles on [securing autonomous AI agents](/blog/ai-agent-security/) and [AI model supply chain security](/blog/ai-model-supply-chain-security/) — those cover the model and its training data; MCP security covers the connective tissue the agent uses to actually reach and act on your systems.

## The specific risks businesses should care about

- **Overscoped permissions.** An MCP server connected to your email, for example, that is granted full read/write/delete access when the actual task only ever needed read access — the common excessive-agency problem, now applied to a concrete integration rather than an abstract agent capability.
- **Unvetted community servers.** A large share of available MCP servers come from community registries with no formal security review, and businesses frequently install them the way they would a browser extension — quickly, and without checking what permissions are actually being requested.
- **Tool poisoning.** A malicious or compromised MCP server can present a tool description that looks legitimate to the AI model but is crafted to manipulate the model's behavior or exfiltrate data through what looks like normal tool use.
- **Token and credential handling.** Many MCP integrations hold long-lived API keys or OAuth tokens to the systems they connect to; a compromised MCP server effectively exposes everything that token can reach.
- **Weak or missing authentication on self-hosted servers.** The newer MCP specification mandates OAuth 2.1 for remote servers, but adoption is uneven, and plenty of internally deployed servers are reachable with no meaningful access control at all.

## A practical MCP security checklist

- [ ] Inventory every MCP server (or MCP-based integration inside a vendor tool) your business actually has connected, including ones installed by individual employees
- [ ] Confirm each server runs with the minimum permission scope the task actually requires — not the broadest scope available
- [ ] Only install MCP servers from vetted sources; treat an unknown community server the same way you would treat an unknown browser extension or npm package
- [ ] Require OAuth 2.1 (or equivalent strong authentication) for any remote MCP server, and confirm self-hosted servers are not reachable from the open internet without authentication
- [ ] Log and monitor MCP tool invocations the same way you would monitor API or admin activity — not as an afterthought to "AI stuff"
- [ ] Map your MCP usage against the OWASP MCP Top 10 and the NSA's MCP security guidance

## Key takeaways

MCP solved a genuine integration problem and is now the default plumbing behind a large share of agentic AI tools businesses are adopting in 2026 — but the pace of adoption has outrun the pace of security hardening, evidenced by dozens of CVEs, hundreds of thousands of exposed servers, and a dedicated OWASP project built specifically to catalog the risk. If your business has turned on any AI integration that reads or writes to your email, files, CRM, or other systems in the past year, it is worth finding out what sits underneath it before assuming the vendor has already secured that layer for you.
